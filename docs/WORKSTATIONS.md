# 锻造台、铁砧和切石机

## 购买与使用

| App | ID | 首次购买材料 | 原版容器 |
|---|---|---|---|
| 锻造台 | `mcphone_workshop:smithing` | 1 个锻造台 | `SmithingMenu` / `MenuType.SMITHING` |
| 铁砧 | `mcphone_workshop:anvil` | 1 个完好的铁砧 | `AnvilMenu` / `MenuType.ANVIL` |
| 切石机 | `mcphone_workshop:stonecutter` | 1 个切石机 | `StonecutterMenu` / `MenuType.STONECUTTER` |

四个平台均提供这三个 App，并保留原工作台 App。主模组要求仍为 MCphone ≥ 1.10.2，
选择对应的 Minecraft／加载器包。联机两端需安装相同版本的附属；本版打开请求协议已更新。

通过 MCphone 公开的 App、价格 SPI 接入商店，原版方块由主模组的购买流程扣除。
各自使用独立的原版隐藏进度作为服务端使用资格；已有工作台资格不会解锁其他 App。
卸载、重装、死亡、重连不主动清除购买记录。创造模式沿用主模组免材料规则。
若历史版本已被 MCphone 记录为购买、附属资格却缺失，首次打开时会根据服务端已购记录补齐，
不重复扣材料。仅客户端有安装图标、服务端没有购买记录的情况不会自动授予资格。
设备检测仍限普通背包和副手，要求玩家存活且不是旁观者。使用时拿走手机／平板会关闭菜单。

点击 App 后离开手机，打开原版界面。服务端继承原版容器，客户端使用原版界面，
沿用原版的同步、按键、配方、物品消耗与关闭返还；没有自定义结果发放或长期材料库存。
请求只接受固定工作站选择器，服务端检查对应购买资格，不接受客户端提供的配方或产物。

## 各工作站的行为

锻造台沿用原版的三个输入格、升级与纹饰配方、模板消耗、物品数据处理和制作事件。
不额外减免模板、装备或材料，数据包配方仍由原版管理器提供。

铁砧按用户选择永久解锁、不会损坏。经验等级消耗、修理材料、改名、附魔合并、
累计修理代价和“过于昂贵”等规则均沿用对应版本的原版与加载器实现。
调用原版 `onTake` 时仅暂停该容器的世界上下文回调，跳过损坏／移除世界铁砧的逻辑；
不会改动玩家脚下或打开菜单时所在位置的真实铁砧。原版加载器事件仍执行，
成功完成原版世界回调请求时，在玩家当前位置播放使用声音。
暂停范围结束后恢复上下文，使关闭返还继续执行；异常时也通过 `finally` 恢复。

切石机沿用原版的输入、配方列表、滚动与选择操作、单次或 Shift 制作、材料消耗及产出比例。
不重写切石配方匹配，数据包配方由原版处理。

## 自动检查与待验收内容

构建会验证四个 App SPI 入口、四个独立购买进度及版本目录。
各目标运行 `testPortableMenus`，使用该版本的真实 `ContainerLevelAccess`，验证：

- 取出铁砧结果期间不执行世界回调，作用域结束后恢复正常回调。
- 取消、异常及嵌套调用不会永久禁用关闭上下文。
- 工作站 ID 与购买记录互相独立，旧工作台 ID 保持不变，无效选择器无法映射到工作站。
- 旧已购记录仅恢复对应工作站；未购买不恢复、已有资格不重复查询、进度缺失不迁移。
- MCphone 实际依赖中的只读购买查询方法签名与兼容桥接一致。

这些检查不代表下列游戏内流程已完成验收。需分别在四个目标的单人和独立服务器确认：

- [ ] 三个 App 均出现在商店中，价格分别为对应原版方块；已有工作台购买仍有效。
- [ ] 生存模式材料不足拒绝购买，充足时只扣一个；损坏铁砧不能代替完好铁砧购买。
- [ ] 三个购买资格独立，重装、重连、死亡及服务端重启后不重复扣费。
- [ ] 未购买的工作站无法通过直接发包打开；负值或超范围选择器无效。
- [ ] 手机、平板、背包、副手检测正常，取走设备、死亡、旁观时不能继续使用。
- [ ] 锻造的升级、纹饰、模板与材料消耗正确，物品组件／NBT 保留正确。
- [ ] 铁砧改名、修理、附魔合并、经验不足、“过于昂贵”、Shift 取出与创造模式符合原版。
- [ ] 在真实铁砧上站立、打开后移动，再连续使用 App，原世界铁砧始终不损坏。
- [ ] 切石机滚动、切换配方、单次与 Shift 制作的输入消耗和产出数量正确。
- [ ] 三个菜单中放入材料后关闭、断线、死亡、换维度或切换 App，材料不会丢失或重复。
- [ ] 数据包配方、相关 Forge／NeoForge 事件及其他模组合成扩展按各自规则工作。
- [ ] 专用服务器不会加载 App 或界面等客户端类。

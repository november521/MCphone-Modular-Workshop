# 便携工作台

## 当前实现

在 MCphone 应用商店消耗一个原版工作台购买 App。购买成功才安装；重复购买与重新安装不重复扣费。点击后发送一个无参数的客户端到服务端请求，
服务端检查玩家已购买、存活、不是旁观者，并在背包或副手携带 `mcphone:phone` / `mcphone:tablet`。
随后打开 `PortableCraftingMenu`，它仅覆写原版 `CraftingMenu` 的有效性条件，
继续使用 `MenuType.CRAFTING`，因此客户端直接显示原版工作台界面。

合成、配方书、物品同步、快捷移动、特殊配方、剩余物、统计和菜单关闭处理均沿用原版。
没有自定义合成协议、客户端发放物品、假工作台方块或长期保存的合成库存。
重复的打开请求不会重开已存在的便携工作台；设备离开有效库存后，服务端会关闭菜单。

服务端传入真实的世界上下文。不能把 `ContainerLevelAccess.NULL` 当作远程工作台捷径：
旧版本的原版工作台通过该上下文执行配方更新和关闭返还，NULL 会跳过这些操作。

只有 `client` 包包含 App 和客户端发包入口，公共初始化不加载 App 实现。
SPI 服务文件由 MCphone 的客户端流程发现。附属不引用 MCphone 内部实现。

## 首版边界

- 通过公开 IAppPriceProvider SPI 报价一个工作台，由 MCphone 服务端购买流程扣除。
- 原版隐藏进度记录服务端使用资格，跨断线、死亡和维度保留；直接伪造打开请求无法跳过购买。
- 创造模式遵循 MCphone 内建物品价格规则，免扣材料。
- 从先前免费版本升级的玩家，需要卸载 App 后重新在商店购买一次。
- 检测普通库存和副手，不读取 Curios / 饰品栏。
- 关闭即结束会话，不保存真实材料或配方模板。
- 关闭后采用原版返回游戏行为，不自动重新弹出手机。
- 两端均需安装附属，当前主模组依赖固定为 MCphone v1.12.0。

## 游戏内验收

下面是待执行的运行验收，编译成功不表示这些项目已在游戏中确认。
应在四个目标上分别验证单人和独立服务端；测试前备份测试存档。

- [ ] 商店显示价格 1 × 工作台，生存模式材料不足时拒绝购买。
- [ ] 购买恰好扣除一个工作台；重复点击、卸载重装和重新登录不重复收费。
- [ ] 未购买者即使伪造打开请求也无法使用，旧免费安装需重新购买。
- [ ] 死亡、换维度、重启服务端后，购买资格仍保留。
- [ ] 从 App 或快捷键打开原版界面，有完整九宫格、背包与配方书。
- [ ] 手机在背包、副手以及平板三种情况均可使用。
- [ ] 没有设备、死亡或旁观者状态的打开请求无效。
- [ ] 关闭、切换界面、断线、死亡及切换维度时，材料总量不增加也不丢失。
- [ ] 合成过程中取走／丢弃手机，菜单关闭且只进行一次材料收尾。
- [ ] 连续点击打开不会反复返还或重建当前工作台。
- [ ] 有序、无序、染色及物品修理等特殊配方正常。
- [ ] 蛋糕等配方正确返还桶，保留物品数据的配方没有丢失组件／NBT。
- [ ] Shift 连续合成、左右键、拖拽分配、数字键和丢弃操作正常。
- [ ] 背包满、鼠标持有物品、结果无法放入时行为与原版一致。
- [ ] 数据包修改的合成配方和 doLimitedCrafting 规则正常。
- [ ] 专用服务器启动时没有加载客户端界面类的错误。
